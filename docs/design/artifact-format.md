# Design invariant: compiled artifacts are version-locked

**Audience:** anyone editing Parséman's encoder, emitter, linker or macro plugin, and
especially the formats they print: the table program (`CompactProgram`, `src/table/program.ts`),
its build-time assemblies (`a:`, `PrecompiledAssembly`), `LinkableTable` pieces
(`src/compiler/compile-linkable-table.ts`) and carried combinator IR
(`src/compiler/ir-serialize.ts`, inline or in a `<chunk>.parseman.json` sidecar).

## The rule

> **A grammar is compiled, and its pieces composed, by the SAME Parséman version.**
> Parséman is not meant to read a compiled artifact produced by a different version. The
> artifact formats may therefore change **freely** between versions and **must not
> carry back-compat shims, `Legacy*` shapes, or dual-format read paths** for an older
> shape. If you find yourself adding a compatibility branch for an older format,
> **STOP**: it is dead code by design.

A package that ships a compiled grammar ships one built by *its* pinned Parséman. A
consumer that composes it does so with its own Parséman, by re-lowering the piece from
its carried IR, never by reading the package's table.

## The stamp, and what is not enforced yet

Every artifact is stamped with the producing version, `PARSEMAN_VERSION` (`src/version.ts`,
kept equal to `package.json` by `test/unit/version-sync.test.ts`):

- the generated-module banner (`// Generated by parseman vX.Y.Z — DO NOT EDIT.`);
- the `v` field of a `LinkableTable`;
- the `parseman` field of a carried-IR sidecar.

**Nothing reads the stamp back today.** No reader compares it with the running version,
so a stale artifact is not rejected with a clear message. That check is
[#186](https://github.com/matthew-dean/parseman/issues/186). Until it lands, the rule above
is a design rule, not a runtime guarantee.

One narrower check does exist. A printed assembly factory opens with
`FACTORY_ARITY_GUARD` (`src/table/emit.ts`): it throws, naming the version that printed
it, when the runtime calling it passes fewer helpers than `EMITTED_PARAMS` had when it
was printed. It counts helpers; it does not compare versions.

## Composition works on rule maps, not on printed tables

`compose()` resolves rule references **by name** over the merged rule map. At run time it
links the live `rules()` maps; in a macro build it re-lowers each piece's carried IR and
encodes the merged map once. Either way, a later piece that overrides rule `X` is the `X`
every reference resolves to, including the earlier piece's own references to it (open
recursion). Nothing composes by editing another build's printed table, which is why a
printed table can change shape freely.

## The shim that always looks necessary

Changing a printed shape makes a `Legacy*` type and a second read branch feel like
ordinary diligence: the new code "should still handle the old shape". It should not. A
second read branch permanently doubles the format's surface. When a shape changes, change
it outright, and say in the CHANGELOG which artifacts must be reprinted.

The rule is about **time, not variety**. At any one version there is exactly one live
shape per artifact kind, and no *older* shape is readable beside it. A different artifact
**kind** (a table program and a sidecar, say) is not a compatibility shim; it carries its
own stamp and obeys the same rule.

## What a runtime does with another version's artifact today

The rule is not enforced, so in practice a newer runtime does run an older artifact: a
package's `parseman/table` resolves to whatever version the consumer installed. The one
shape that meets this is the emitted-assembly factory, which takes its helpers in
`EMITTED_PARAMS` order (`src/table/emit-assembly.ts`):

- **Helpers are appended, never removed or reordered, within a minor.** A factory printed
  by an earlier version declares a prefix of the list and ignores the trailing arguments,
  so it still binds every helper it names. 0.59.0 relies on this for its constructor
  helpers.
- **A factory refuses an older runtime.** `FACTORY_ARITY_GUARD` (`src/table/emit.ts`)
  throws, naming the printing version, when the runtime passes fewer helpers than the
  factory was printed with.
- **Removing a helper breaks every factory printed before it**, and a factory printed
  before 0.59.0 has no guard, so it would bind the wrong helpers. Such a change belongs
  in a minor and must also add a runtime-side check of the factory's declared parameter
  count.
- **Helpers are never reordered.** A reorder keeps the count, so neither guard would see
  it. One would need a check of the order itself (an ABI identifier printed with the
  factory), which does not exist.
